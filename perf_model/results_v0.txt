Configuration under test: CM-100 (12x12=144 MACs, 128 KB, 16 banks x 8 B = 128 B/cyc, 8 merged FMAs = 16 fp32 lanes / 8 fp64, 800 MHz, T1)

  Compare against the tile-size table above. If bandwidth moves the solver
  rows more than MAC count does, then the correct architecture is a WIDE,
  heavily-banked scratchpad with a MODEST array — not a big systolic tile.
  That is a Phase-1 microarchitecture decision worth getting right.

  CAUTION — the table above is the OPTIMISTIC reading. It assumes (a) the
  full fetch width is usable on every GEMV row, which needs SEGMENTED
  REDUCTION in the RTL, and (b) the vector unit is not the bottleneck.
  Same sweep with segmented reduction ABSENT (tail beat of each matrix
  row wasted) — this is what you get if that RTL feature is skipped:
benchmark       B/cyc=16    B/cyc=32    B/cyc=64   B/cyc=128   B/cyc=256
QUAD-MPC           236.9       126.4        71.1        49.0        37.9

  And the vector unit becomes the co-bottleneck past ~128 B/cycle: on
  QUAD-MPC with 8 fp32 lanes, vector+transcendental work is a fixed 720
  cycles/iteration, so it caps the achievable speedup regardless of
  scratchpad width. See perf_model/cm100_sizing.py for the full costing
  (area, energy, bank conflicts) behind the bandwidth-first decision.

====================================================================================================
CAVEATS (do not quote these numbers externally)
====================================================================================================
  1. Energy constants are scaled estimates, not PDK numbers (+/-2x).
  2. CPU small-GEMM efficiency (30%) is a literature-informed guess; measure
     it on real hardware with OSQP/acados before trusting any ratio.
  3. Sequencer cost is now DESCRIPTOR-DERIVED (issue rate + dependency
     drain + loop-carried scalar chain), not the old flat 50%-overlap
     fudge -- see perf_model/sequencer.py. The load-bearing [EST] is
     seq_setup_cycles = 4 cycles/descriptor; count the instructions in a
     real RV32 descriptor-emit sequence to firm it up.
  4. No thermal, DVFS, or contention modelling.
  5. Next fidelity step: measure the CPU baselines for real (Phase 0), then
     replace the CM side with the cycle-approximate model (Phase 1).
