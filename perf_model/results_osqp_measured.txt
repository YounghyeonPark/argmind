Host: x86_64 (this machine). TIMES DO NOT TRANSFER TO Arm — iteration
counts and problem structure do. Compare only the iteration counts to the model.

PROBLEM STRUCTURE
  decision variables (N*n_u)      : 80
  constraint ROWS, real OSQP form : 320   (input box 80 + state box 240)
  constraint rows assumed by model: 640   (2*n_var + 2*N*n_x)
  -> model overcounts constraints by 2.0x
     Cause: OSQP expresses a two-sided bound l<=Ax<=u as ONE row; the model
     counts two. This inflates the A@x and A.T@y terms in every solver row.

  nnz(P)=6400  nnz(A_con)=8776  density(P)=1.00   [COUPLED plant, correct]
  nnz(P)=1600  nnz(A_con)=2328  density(P)=0.25   [decoupled plant, FLAWED v1]
  The first harness version used inputs [thrust,tau_x,tau_y,tau_z] with a
  diagonal inertia and no drag, which decouples into 4 independent SISO
  channels -> 4-block-diagonal Hessian at 25% density. Nobody solves that as
  one 80-var QP. Fixed: inputs are now the 4 rotor thrusts through the mixing
  matrix, plus drag and gyroscopic coupling. Both are measured below.

  'cold' = first solve, no warm start.
  'settle' = return to hover then hold -- the EASIEST warm-start case.
  'aggressive' = reference steps + disturbances forcing active-set changes;
  this is the distribution a hard real-time deadline must be sized against,
  and the tail (p99/max), not the median, is what determines feasibility.
  Default OSQP settings would report all of these quantised to multiples of 25.
